## Context

The repository had just completed `M-105/W-0177`, the presence lifecycle functional slice. The next ready work item was `M-106/W-0178`, the presence protocol query functional slice.

The maintainer wanted to preserve project intent in the repository itself so a future Codex session can continue directly from the directory without depending on the current conversation.

## Maintainer Narrative

The maintainer said:

```text
我们精修一下目标吧，然后落到文档里。下次我说继续推进，就可以接着做。不，也不用现在的上下文，我直接在这个目录底下按Codex，然后就能接着做。因为我最近可能要暂停一下这个项目，我现在没有那么多Token来跑这个了。我们下一步的短期目标就是做一个0.1出来。然后呢把我们的README也改一下，让真正想要试的用户能够下载下来试一试，或者加入到我们的开发的队伍中来。然后远期目标我们肯定是要做一个AI时代的Pitaia或者Nakama。
```

Key intent:

- The repository should be self-resuming for future Codex sessions.
- The short-term goal is a `0.1` release.
- The README should serve real users and contributors, not only internal agents.
- Long term, vibit should be an AI-era Pitaya or Nakama.

## Agent Response Summary

The agent treated this as a lightweight roadmap and documentation slice.

The change records:

- `v0.1 alpha` as the short-term developer-usable release target;
- AI-era Nakama/Pitaya-class server framework as the long-term target;
- `M-106/W-0178` as the next immediate continuation step;
- the recommended near-term sequence from presence query to onboarding, authenticated E2E, runbook, example client, health/readiness/config surface, and alpha acceptance check;
- README updates for external users and contributors.

## Decisions

- Accept `ADR-0086`.
- Add `docs/v0.1-alpha-goal.md` and the paired Simplified Chinese translation.
