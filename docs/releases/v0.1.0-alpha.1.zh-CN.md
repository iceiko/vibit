# v0.1.0-alpha.1

`v0.1.0-alpha.1` 是 vibit 的第一个 source-first alpha，面向想要检查和试用 agent-native game/backend server framework 的开发者。

本 release 刻意保持很小：只通过 Git tag 和 GitHub release record 发布仓库源码。它不包含 binaries、packages、containers、checksums、signing/provenance artifacts、hosted deployments、install scripts、SDKs 或 registry publication。

## 为什么值得试

vibit 围绕一个具体判断构建：backend frameworks 应该更容易被 AI coding agents 和人类理解、扩展、验证和维护。这个仓库把 architecture rules、module boundaries、contracts、decisions、change specs 和 verification commands 显式化，而不是让它们只存在于聊天记录或 maintainer 记忆里。

## 当前可以检查什么

- `runtime/` 下的 Go runtime。
- `/v1/ws` WebSocket gameplay endpoint。
- Protobuf envelope 和 generated Go Protobuf output。
- PostgreSQL migration sources 和 persistence adapters。
- Device credential login、opaque access-token validation、runtime session metadata、first-message connection binding、protected inventory、protected presence query 和 logout behavior。
- Health、readiness、version 和 redacted config endpoints。
- `examples/local-alpha-request-loop.sh` 中的 redacted local alpha request loop。
- 通过 `CONSTITUTION.md`、`AGENTS.md`、`.arch/`、`changes/`、`decisions/` 和 `tools/vibit` 保存的 agent-readable project memory。

## 试用路径

```bash
git clone https://github.com/iceiko/vibit.git
cd vibit
node tools/vibit check all
cd runtime && go test ./...
cd .. && examples/local-alpha-request-loop.sh
```

Request loop 包装 focused authenticated gameplay proof，并避免打印 raw credentials、raw access tokens、verifier keys、DSNs、digests 或 transport metadata。

## 当前限制

这是 alpha source release，不是 production server distribution。本 release 继续排除 hosted deployment、binaries、packages、containers、checksums、signing/provenance artifacts、SDKs、broad operations/admin behavior、additional product modules 和 direct Nakama/Pitaya API compatibility。

## 下一方向

项目下一个有边界的方向是 first alpha user discovery：让 README 和 release surface 更有效，找到第一批真正感受到 agent-maintainability 问题的开发者，并把他们的 friction 转化为下一批具体 work queue items。
