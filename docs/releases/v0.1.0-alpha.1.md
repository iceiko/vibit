# v0.1.0-alpha.1

`v0.1.0-alpha.1` is vibit's first source-first alpha for developers who want to inspect and try an agent-native game/backend server framework.

This release is intentionally small: it publishes the repository source through a Git tag, GitHub release record, and GitHub source archive. It does not include binaries, packages, containers, checksums, signing/provenance artifacts, hosted deployments, install scripts, SDKs, or registry publication.

## Why Try It

vibit is built around a specific idea: backend frameworks should be easier for AI coding agents and humans to understand, extend, verify, and maintain. The repository makes architecture rules, module boundaries, contracts, decisions, change specs, and verification commands explicit instead of leaving them in chat history or maintainer memory.

## What You Can Inspect Today

- Go runtime under `runtime/`.
- WebSocket gameplay endpoint at `/v1/ws`.
- Protobuf envelope and generated Go Protobuf output.
- PostgreSQL migration sources and persistence adapters.
- Device credential login, opaque access-token validation, runtime session metadata, first-message connection binding, protected inventory, protected presence query, and logout behavior.
- Health, readiness, version, and redacted config endpoints.
- A redacted local alpha request loop at `examples/local-alpha-request-loop.sh`.
- Agent-readable project memory through `CONSTITUTION.md`, `AGENTS.md`, `.arch/`, `changes/`, `decisions/`, and `tools/vibit`.

## Try Path

```bash
git clone https://github.com/iceiko/vibit.git
cd vibit
node tools/vibit check all
cd runtime && go test ./...
cd .. && examples/local-alpha-request-loop.sh
```

The request loop wraps the focused authenticated gameplay proof and avoids printing raw credentials, raw access tokens, verifier keys, DSNs, digests, or transport metadata.

## Current Limits

This is an alpha source release, not a production server distribution. The release keeps hosted deployment, binaries, packages, containers, checksums, signing/provenance artifacts, SDKs, broad operations/admin behavior, additional product modules, and direct Nakama/Pitaya API compatibility out of scope.

## Next Direction

The next bounded project direction is first alpha user discovery: make the README and release surface work harder, find the first developers who feel the agent-maintainability problem, and turn their friction into the next concrete work queue items.
