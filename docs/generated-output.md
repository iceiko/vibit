# Generated Output Standard

Status: Draft v0.1
Last updated: 2026-05-14
Scope: Generated files under `runtime/internal/generated/`

This standard defines how vibit treats generated files once source contracts, schemas, and Protobuf files start producing runtime code.

Use this standard together with `CONSTITUTION.md`, `.arch/runtime.yaml`, `.arch/protocol.yaml`, and `ADR-0017`.

## 1. Purpose

Generated files are part of vibit's agent-native architecture.

They reduce repetitive work, preserve consistent structure, and make framework shape predictable for future agents. They also create risk: if an agent silently hand-edits generated output to fix a local problem, the repository may drift away from its source contracts and generators.

This standard keeps generated output inspectable, reproducible, and clearly separated from handwritten logic.

## 2. Source Before Output

Generated files must trace to source artifacts.

Valid sources may include:

- Contract source files under `contracts/`.
- Module manifests under `modules/<module>/module.yaml`.
- Protobuf source files under `proto/`.
- Generator templates and configuration.
- Architecture manifests under `.arch/`.

If generated output is wrong, agents should change the source contract, schema, Protobuf file, template, or generator. They must not patch generated output directly unless a change spec or Agent Decision Record explicitly grants `generated_file_override`.

## 3. Generated Roots

Current generated output roots:

```text
runtime/internal/generated/contracts/
runtime/internal/generated/proto/
```

`runtime/internal/generated/contracts/` is reserved for generated Go contract shapes.

`runtime/internal/generated/proto/` is reserved for generated Go Protobuf output from `.proto` files under `proto/`.

Handwritten runtime logic must not live under these directories.

## 4. Go Protobuf Output

Go Protobuf output is generated by `protoc-gen-go`, orchestrated by Buf.

Source files:

```text
proto/**/*.proto
```

Configuration:

```text
buf.yaml
buf.gen.yaml
```

Output root:

```text
runtime/internal/generated/proto/
```

Allowed file shape under `runtime/internal/generated/proto/`:

```text
**/*.pb.go
```

Temporary `.gitkeep` files are allowed while a generated directory has no generated files.

Generated Go Protobuf files must include the standard generated-code marker emitted by `protoc-gen-go` and a source trace comment that maps back to an existing `.proto` file.

Agents must not create handwritten `.go` files under `runtime/internal/generated/proto/`.

## 5. Go Contract Shape Output

Go contract shape output is generated by vibit tooling from semantic contract manifests.

Source files:

```text
contracts/**/*.yaml
```

Generation command:

```bash
node tools/vibit generate contract-shapes all
```

Output root:

```text
runtime/internal/generated/contracts/
```

Allowed file shape under `runtime/internal/generated/contracts/` for non-runtime modules:

```text
<module>/<contract-type>/<ContractID>.go
```

Runtime contract families require a family-aware path:

```text
runtime/<family>/<contract-type>/<ContractID>.go
```

The first planned runtime family-aware path is:

```text
runtime/authentication/<contract-type>/<ContractID>.go
```

The authentication family timing and boundary are defined in `docs/authentication-generated-contract-shape-timing.md` and `ADR-0038`. Runtime authentication shape files remain deferred until a later work item explicitly updates generator/check support and generates those files.

Generated contract shape files are inspectable summaries. They do not implement command handlers, query handlers, event publication, persistence, authentication, WebSocket routing, or Protobuf envelope behavior.

Generated contract shape files must include:

```text
Code generated by vibit generate contract-shapes. DO NOT EDIT.
Source: <contract source path>
Generator: tools/vibit generate contract-shapes
Contract: <module>:<type>:<id>
```

Runtime family-aware generated contract shapes must also expose the runtime family, either in the contract trace or in a separate generated field. For the first authentication family, the family value is `authentication`.

## 6. Trace Requirements

A generated file should make these facts discoverable:

- It is generated.
- Which source artifact produced it.
- Which generator or generation command produced it.
- Which output root owns it.

For Go Protobuf output, the standard `protoc-gen-go` header is enough for generated-code identity and source tracing. The expected source trace is the generated comment:

```text
// source: <path>.proto
```

The source trace must resolve to an existing file under `proto/`.

For vibit-owned generators, generated files should include:

```text
@generated
Source: <source artifact>
Generator: <generator identity>
```

## 7. Agent Rules

Agents must:

- Read this standard before changing generated output, generator behavior, or generated output manifests.
- Change source artifacts before generated output.
- Keep generated output out of handwritten module logic.
- Run `node tools/vibit check generated` after adding, removing, or changing generated files.
- Run `node tools/vibit generate contract-shapes all` instead of hand-editing generated contract shapes.
- Record generation commands and unavailable tooling in the relevant change verification.

Agents must not:

- Hand-edit generated files without `generated_file_override`.
- Put business logic under `runtime/internal/generated/`.
- Add handwritten protocol adapters under `runtime/internal/generated/proto/`.
- Add handwritten runtime logic under `runtime/internal/generated/contracts/`.
- Commit generated Go Protobuf files that do not trace to existing `.proto` sources.
- Commit generated contract shape files that do not reproduce from contract source files.
- Claim generation was run when the local toolchain was unavailable.

## 8. Verification

Current verification:

```bash
node tools/vibit check generated
node tools/vibit check protocol
node tools/vibit inspect generated --json
node tools/vibit check all
```

`check generated` verifies module-declared generated files and the Go Protobuf output root. For `runtime/internal/generated/proto/`, it allows an empty planned directory, permits `.gitkeep`, requires generated Protobuf Go files to use the `*.pb.go` suffix, requires the `protoc-gen-go` generated-code marker, and requires a source trace that resolves to an existing file under `proto/`.

For `runtime/internal/generated/contracts/`, `check generated` verifies that each registered non-runtime semantic contract has a generated Go contract shape, that the shape declares source and generator traces, and that the committed file matches the current generator output.

Runtime family-aware contract shapes require generator and check support before they may be committed. The first planned family is `runtime/authentication`, and the required checks are defined in `docs/authentication-generated-contract-shape-timing.md`.

Future verification should add:

- Generator reproducibility checks.
- Generated output drift checks.
- Import-boundary checks for generated packages.
- Checks that generated contract files trace to contract manifests and generator versions.

## 9. Migration Path

Before generated files are committed:

1. Keep output directories as skeleton directories with `.gitkeep`.
2. Stabilize source contracts, `.proto` files, and generation configuration.
3. Run `node tools/vibit check generated`.
4. Run `buf lint` and `buf generate` only when the local Buf and Go Protobuf toolchain is available.
5. Commit generated output only if it passes source trace and ownership checks.

If generated output is already committed and a source mismatch is found, update the source artifact or generator, regenerate, and record the verification path.
